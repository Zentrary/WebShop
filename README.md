# ZenMarket

ร้านค้าออนไลน์แบบ SPA ที่ทำงานบน Vite + Supabase — ลูกค้าสมัครสมาชิกเพื่อสั่งซื้อ ชำระเงินผ่าน PromptPay และติดตามคำสั่งซื้อ ส่วนเจ้าของร้านจัดการสินค้า หมวดหมู่ รีวิว และการตั้งค่าร้านได้จากหลังบ้าน

## ฟีเจอร์

- **หน้าบ้าน** — โฮเพจเรื่องราว สถิติ ขั้นตอน รีวิวจากฐานข้อมูล (ว่างก็บอกว่า “ยังไม่มีรีวิว”) และ FAQ
- **ร้านค้า** — รายการสินค้าพร้อมชิปกรองหมวดหมู่ในหน้าเดียว หน้ารายละเอียดสินค้า ตะกร้า และเช็กเอาต์ (ผู้เข้าชมต้องสมัครสมาชิกก่อน)
- **บัญชีสมาชิก** — โปรไฟล์ ที่อยู่จัดส่ง รายการโปรด คำสั่งซื้อ และสินค้าที่ชอบ
- **หลังบ้านเจ้าของร้าน** — แดชบอร์ดพร้อมกราฟยอดขาย 7 วัน, จัดการสินค้า, จัดการหมวดหมู่ (เพิ่ม/เปลี่ยนชื่อ/ลบพร้อมย้ายสินค้า), รีวิว, อนุมัติคำสั่งซื้อ, ตั้งค่าร้าน และสำรอง/กู้คืนข้อมูลแบบเข้ารหัส
- **ระบบหลายภาษา** — ไทย/อังกฤษ สลับได้ทันทีโดยไม่ต้องโหลดหน้าใหม่

## โครงสร้าง URL

เว็บใช้ clean URL ไม่มี `.html` ต่อท้าย — `/home`, `/shop`, `/shop/product?id=…`,
`/account/orders`, `/admin/dashboard` ฯลฯ

- บน Vercel เปิดด้วย `"cleanUrls": true` ใน `vercel.json` และมี 308 redirect
  รองรับลิงก์เก่าทั้งแบบ `.html` (`/login.html`) และแบบที่ถูกตัด `.html` แล้ว
  (`/login`) ให้ไปหน้าที่ถูกต้อง — เพราะ Vercel ตัด `.html` ให้ก่อนถึงขั้น redirects
- ตอน `npm run dev` / `npm run preview` มีปลั๊กอินเล็ก ๆ ใน `vite.config.js`
  แปลง `/home` → `home.html` และ `/shop` → `shop/index.html` ให้เหมือนของจริง

| ส่วน                 | รายละเอียด                                                                                                                                    |
| ------------------- | -------------------------------------------------------------------------------------------------------------------------------------------- |
| ราคาโปรโมชั่น         | ใส่ `sale_price` ที่ต่ำกว่าราคาปกติได้ การ์ดสินค้าและหน้าสินค้าจะขีดราคาเดิมและติดป้ายลดราคา ตะกร้าและเช็กเอาต์คิดราคาที่จ่ายจริง                                     |
| คูปองส่วนลด           | `/admin/coupons` สร้างโค้ดแบบเปอร์เซ็นต์หรือจำนวนเงิน กำหนดยอดซื้อขั้นต่ำ จำนวนครั้ง และวันหมดอายุ — ลูกค้ากรอกโค้ดใน `/shop/checkout` แล้วตรวจกับเซิร์ฟเวอร์ก่อนใช้   |
| ที่อยู่ที่บันทึกไว้          | ลูกค้าเก็บที่อยู่ได้หลายรายการในหน้าบัญชี และเลือกเติมในเช็กเอาต์ได้ในคลิกเดียว                                                                                |
| ตรวจสลิปโดยเจ้าของร้าน | ไม่มีผู้ให้บริการ API ตรวจสลิปฟรีที่เชื่อถือได้ ระบบจึงให้แอดมินเปิดดูสลิปทีละใบที่ `/admin/orders` แล้วกดอนุมัติหรือตีกลับพร้อมเหตุผล สถานะและเหตุผลแสดงให้ลูกค้าเห็นในหน้าคำสั่งซื้อ |
| รายงานยอดขาย        | `/admin/reports` สรุปช่วงวันที่ เลือกช่วงแล้วดาวน์โหลด CSV ได้                                                                                         |
| สต็อกใกล้หมด          | ตั้งเกณฑ์แจ้งเตือนในหน้าตั้งค่า (ค่าเริ่มต้น 5) และดูรายการสินค้าใกล้หมดบนแดชบอร์ด                                                                             |
| ข้อความหน้าเว็บ        | แก้ข้อความหน้า เกี่ยวกับเรา / ช่วยเหลือ / นโยบายความเป็นส่วนตัว ได้จากหน้าตั้งค่า (เก็บในตาราง `site_pages` แยกภาษาไทย–อังกฤษ)                                 |
| หน้า 404 และคุกกี้      | มีหน้า `404.html` ของร้านเอง และแถบขอความยินยอมคุกกี้ที่จำคำตอบไว้ในเบราว์เซอร์                                                                          |

## เริ่มใช้งาน

```bash
npm install
cp .env.example .env      # ใส่ VITE_SUPABASE_URL และ VITE_SUPABASE_ANON_KEY
npm run dev               # http://localhost:5173
```

### ตัวแปรสภาพแวดล้อม

```env
VITE_SUPABASE_URL=https://<project-ref>.supabase.co
VITE_SUPABASE_ANON_KEY=<anon-key>
```

ค่าทั้งสองเป็นคีย์ฝั่งผู้ใช้เท่านั้น — สิทธิ์จริงทั้งหมดถูกบังคับด้วย RLS บนฝั่งฐานข้อมูล

### บัญชีทดสอบ (โปรเจกต์ MarketWeb)

| บทบาท   | อีเมล                      | รหัสผ่าน          | ชื่อผู้ใช้      | หน้าเข้าสู่ระบบ    |
| ------- | ------------------------- | --------------- | ---------- | -------------- |
| ลูกค้า    | `user@zenmarket.example`  | `ZenUser#2026`  | `zenuser`  | `/auth/login`  |
| ผู้ดูแลร้าน | `admin@zenmarket.example` | `ZenAdmin#2026` | `zenadmin` | `/admin/login` |

ผู้ดูแลร้านสามารถเข้าสู่ระบบด้วยทั้งอีเมลหรือชื่อผู้ใช้ (`zenadmin`) — หน้า admin login จะแปลงชื่อผู้ใช้เป็นอีเมลให้อัตโนมัติ

ลูกค้าที่เข้าสู่ระบบจะถูกพากลับไปที่ `/home` (หรือกลับไปหน้าที่ตั้งใจจะไปก่อนถูกขอให้ล็อกอิน)

## ความปลอดภัย

- **RLS เป็นแกนหลัก** — ทุกตารางเปิด Row Level Security; RPC ที่เขียนข้อมูลใช้ `SECURITY DEFINER` และตรวจ `auth.uid()` ทุกครั้ง
- **ราคาและสต็อกถูกคำนวณบนเซิร์ฟเวอร์** — ไคลเอนต์ส่งแค่รหัสสินค้าและจำนวน ราคาจริงถูกดึงจากฐานข้อมูลตอนสร้างออเดอร์
- **จำกัดความถี่การเข้าสู่ระบบ** — `login_allow` และ `create_order` มี rate limit ต่อบัญชี/ต่อ IP
- **ส่งออกข้อความอย่างปลอดภัย** — HTML escape ทุกจุดที่แทรกข้อมูลผู้ใช้ และกรอง URL ปลอมภัย (`safeLink`, `safeImage`)
- **ส่วนหัวความปลอดภัย** — CSP, HSTS, `X-Frame-Options`, `Referrer-Policy`, `Permissions-Policy`
- **รหัสผ่าน** — อย่างน้อย 8 ตัว ต้องมีตัวอักษรและตัวเลข พร้อมตัวบอกสถานะแบบทันที
