# การติดตามพัสดุ (order tracking)

สรุปว่าระบบตอนนี้ทำอะไรได้ ทำไม่ได้ และจะอัปเกรดเป็น "สถานะอัปเดตเอง" ได้อย่างไรโดยไม่ต้องจ่ายเงิน

---

## 1. สิ่งที่ทำได้แล้ว (ฟรี 100% ไม่ใช้ API ภายนอก)

| ส่วน | พฤติกรรม |
| --- | --- |
| หน้าแอดมิน `/admin/order` | กรอกเลขพัสดุ → ระบบ **เดาชนส่ง** จากรูปแบบเลขให้ (ไปรษณีย์ไทย, KEX, SPX) แล้วเลือกเองได้จาก dropdown |
| ปุ่ม "เปิดหน้าตรวจสอบพัสดุ" | เปิดหน้าตรวจสอบของขนส่งเจ้านั้นในแท็บใหม่ (ไปรษณีย์ไทยเติมเลขให้อัตโนมัติ) |
| หน้า `/admin/order` ของออเดอร์ที่จัดส่งแล้ว | แก้เลขพัสดุ/ขนส่งที่พิมพ์ผิดได้ โดยไม่ต้องเปลี่ยนสถานะ (เดิมแก้ไม่ได้) |
| หน้า `/account/order` ของลูกค้า | การ์ด "การติดตามพัสดุ" แสดงขนส่ง + ลิงก์หน้าตรวจสอบ + ปุ่มคัดลอกเลขพัสดุ |
| ฐานข้อมูล | `orders.carrier` = `thailand_post \| kex \| flash \| jt \| spx \| other` (null = ไม่ระบุ) |

ข้อดี: ไม่มีโควตา ไม่มีค่าใช้จ่าย ไม่ต้องเก็บคีย์ลับ และใช้ได้ทุกขนส่ง
ข้อจำกัด: สถานะพัสดุ **ไม่ถูกดึงมาแสดงในเว็บ** ลูกค้าต้องกดลิงก์ไปดูที่หน้าขนส่ง

---

## 2. ถ้าอยากให้สถานะอัปเดตเอง (ยังประหยัด/ฟรี)

สถานะพัสดุต้องดึงจาก API ของขนส่ง ซึ่ง **ห้ามเรียกจากหน้าเว็บตรง ๆ** เพราะคีย์จะหลุดไปกับ JS
เส้นทางที่ถูกคือ: ตั้งคีย์เป็นความลับฝั่งเซิร์ฟเวอร์ → เรียก API → เขียนสถานะลงฐานข้อมูล → หน้าเว็บอ่านจากฐานข้อมูล

| ทางเลือก | ฟรีแค่ไหน | ครอบขนส่ง |
| --- | --- | --- |
| ไปรษณีย์ไทย Track API (สมัครฟรีที่ track.thailandpost.co.th) | ฟรี + มี webhook (โควตาราว 1,000 เลข/วัน) | ไปรษณีย์ไทยเท่านั้น |
| 17TRACK API | 100 เลขใหม่/เดือน (เช็กซ้ำไม่กินโควตา) | 3,300+ รวม KEX / Flash / J&T / Best / SPX |
| ETrackings (ไทย) | 50 ครั้ง/เดือน (ไม่มีไปรษณีย์ไทย ไม่มี webhook) | 13 เจ้า |

สิ่งที่ต้องทำเพิ่มเมื่อมีคีย์แล้ว

1. ตาราง `order_tracking_events` เก็บ timeline (มี unique กันข้อมูลซ้ำ)
2. ตัวเชื่อมฝั่งเซิร์ฟเวอร์ (Vercel function หรือ Supabase Edge Function) เก็บคีย์ใน env
3. cron ทุก 30 นาที ดึงเฉพาะออเดอร์ที่ยังไม่ `delivered` และไม่เกิน 30 วัน
4. map สถานะขนส่ง → สถานะร้าน: รับเข้าระบบ = `shipped`, นำจ่ายสำเร็จ = `delivered`
5. หน้าเว็บแสดง timeline ใต้การ์ดติดตามพัสดุ (ยังใช้ `orders.status` 5 ค่าเดิม ไม่ต้องแก้ constraint)

> หมายเหตุ: ต่อให้ดึงทุกนาที ข้อมูลจากขนส่งเองก็อัปเดตทุก ~15 นาทีถึงไม่กี่ชั่วโมง "เรียลไทม์" จึงไม่ต่างจากการดึงทุก 30 นาที
