# หมวดหมู่สินค้า + หมวด "สินค้าใหม่" อัตโนมัติ

> อัปเดต 24 พ.ย. 2026 — ใช้งานได้แล้วทั้งหลังบ้านและหน้าร้าน (ระบบ "ตั้งเวลาเปิดขาย" ถูกถอดออกแล้ว)

## 1) เพิ่มหมวดหมู่ใหม่ได้จากฟอร์มสินค้าเลย

เดิม: ช่อง "หมวดหมู่" ในฟอร์มสินค้าเป็นช่องพิมพ์อิสระ การพิมพ์ชื่อใหม่ **ไม่** สร้างหมวดในตาราง `categories`
ผลคือชิปกรองที่หน้า `/shop` ไม่มีหมวดนั้น เพราะหน้าร้านอ่านหมวดจากตาราง `categories` เท่านั้น

ตอนนี้:

- ช่องหมวดหมู่มี **datalist** เด้งรายชื่อหมวดที่มีอยู่ให้เลือก/พิมพ์ซ้ำ
- พิมพ์ชื่อใหม่แล้วกด "บันทึกสินค้า" → ระบบสร้างแถวใน `categories` ให้อัตโนมัติ (ถ้าซ้ำจะไม่สร้างซ้ำ)
- ชิปที่หน้า `/shop` ขึ้นทันทีโดยไม่ต้องไปเพิ่มที่หน้า "หมวดหมู่" ก่อน

ยังจัดการหมวดแบบเต็มได้ที่ **หลังบ้าน → หมวดหมู่** (เพิ่ม / เปลี่ยนชื่อ / ลบ) เหมือนเดิม

## 2) หมวด "สินค้าใหม่" (สินค้าอยู่ชั่วคราวแล้วกลับเข้าหมวดเดิมเอง)

นี่คือของที่ร้านขอ: โพสต์ของชิ้นใหม่ → ลูกค้าเห็นในหมวดใหม่ → ครบ N วันของกลับไปอยู่หมวดจริงของมัน

- หน้า `/shop` มีชิป **"สินค้าใหม่"** เป็นอันที่สองถัดจาก "ทั้งหมด" (ไม่ต้องสร้างหมวดเอง ระบบทำให้)
- ตั้งจำนวนวันได้ **ต่อสินค้า** ที่ฟิลด์ *อยู่ในหมวด "ใหม่" (วัน)* — เช่น 2 วัน (0 = ไม่ต้องขึ้นหมวดใหม่, สูงสุด 365)
- ระหว่างนั้นการ์ดมีป้าย **"ใหม่"** สีเขียว
- ครบกำหนด → สินค้าหลุดจากหมวด "ใหม่" **เอง** แต่ยังอยู่ในหมวดจริง (เช่น อุปกรณ์อิเล็กทรอนิกส์) ตามปกติ **ไม่มีการย้ายข้อมูล ไม่ต้องกดอะไร**
- หลังบ้านโชว์ใต้ชื่อสินค้าว่า **"ใหม่ถึง 26/11/2026"** จะได้รู้ว่าอีกกี่วันจะกลับเข้าหมวด
- การ์ดสินค้าทุกใบแสดง **วันที่โพสต์** เป็นเลข `วว/ดด/ปปปป` (ไม่แสดงเวลา)

## 3) ทำไมต้องแก้ที่ฐานข้อมูล ไม่ใช่แค่ซ่อนที่หน้าจอ

ถ้าซ่อนแค่ในเบราว์เซอร์ ใครเปิด F12 ก็ยิง REST API ดึงสินค้าที่ยังไม่เปิดขายไปได้ (รวมราคา/สต็อก) จึงบังคับที่ชั้นข้อมูล:

```sql
-- products.new_days, products.new_until (คำนวณโดย trigger)
-- policy อ่าน products: ลูกค้าเห็นเฉพาะ active AND (publish_at is null OR publish_at <= now())
--                    แอดมินยังเห็นทุกแถว
-- create_order_reserved_internal: ห้ามขายสินค้าที่ยังไม่ถึงเวลา
```

ไฟล์: [`015_new_arrivals_window.sql`](../supabase/migrations/015_new_arrivals_window.sql) (หน้าต่าง "ใหม่")
และ [`016_remove_scheduled_publishing.sql`](../supabase/migrations/016_remove_scheduled_publishing.sql) (ถอดระบบตั้งเวลาเปิดขาย)
(apply กับโปรเจกต์จริงแล้ว — คอลัมน์ใหม่เป็น `null` ทั้งหมด สินค้าเดิมจึงยังขายได้ตามปกติ)

## 5) สิ่งที่ถูกถอดออก (ตามที่ร้านเลือก "ลบจริง")

ระบบ "ตั้งเวลาเปิดขาย + แถบกำลังจะมา" จากรอบก่อนถูกลบออกทั้งหมด ไม่ใช่แค่ซ่อน:

| ชั้น | สิ่งที่ลบ |
| --- | --- |
| ฐานข้อมูล | คอลัมน์ `products.publish_at`, `products.show_soon`, index `products_publish_at_idx` |
| ความปลอดภัย | policy อ่านสินค้ากลับเป็น `active OR is_admin()` · ฟังก์ชัน `create_order_reserved_internal` กลับไปเป็น `where ... and active for update` |
| Trigger | `products_set_new_until` เลิกอ้าง `publish_at` แล้ว (นับจากวันโพสต์เท่านั้น) |
| หน้าร้าน | แถบ "กำลังจะมา", ตัวนับถอยหลัง, ตัวกรอง `publish_at` ในรายการ/สินค้าที่เกี่ยวข้อง |
| หลังบ้าน | ช่อง "ตั้งเวลาเปิดขาย" และ "แสดง 'เร็ว ๆ นี้'", ป้าย "ตั้งเวลา …" ในตาราง |
| CSS / i18n | `.coming-soon*`, `.coming-card*`, `.soon-badge`, `.coming-countdown` และคีย์ข้อความที่เกี่ยวข้อง |

หลังบ้านเหลือช่องเดียวที่เกี่ยวกับเวลา: **อยู่ในหมวด "ใหม่" (วัน)**
